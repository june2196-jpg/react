# Commit

변경사항을 안전하고 이해하기 쉬운 커밋으로 남긴다. 커밋 요청은 즉시 커밋할 권한을 포함하며, 별도의 승인 단계 없이 진행한다.

## 절차

1. 저장소 상태를 확인하고 `git diff`로 작업 트리 변경사항을 분석한다. 스테이징된 변경이 있다면 `git diff --staged`도 확인한다.
2. 변경을 목적과 영향 범위가 함께 이동해야 하는 논리적 단위로 분류한다. 서로 독립적인 기능, 수정, 정리, 설정 변경은 가능한 한 별도 커밋으로 제안한다. 사용자의 기존·무관한 변경은 포함하지 않는다.
3. 각 단위에 다음 형식의 한국어 커밋 메시지를 작성한다.

   ```text
   <type>: <간결한 한국어 요약>
   ```

   `type`은 변경 성격에 맞춰 `feat`, `fix`, `refactor`, `chore` 중 선택한다. 메시지는 구현 수단보다 사용자 또는 코드베이스 관점의 결과를 설명한다.
4. 각 단위에 해당하는 파일만 스테이징하고 즉시 커밋한다. 여러 단위이면 의존성이 낮은 변경부터 순서대로 커밋한다.
5. 커밋 후 `git status --short`와 최근 커밋을 확인해, 생성한 커밋과 메시지를 보고한다.

## 경계와 예외

- 변경사항이 없으면 커밋하지 말고 그 사실을 알린다.
- 이미 스테이징된 변경은 작업 트리 변경과 구분하고, 커밋 단위에 포함되는 파일만 추가로 스테이징한다. 무관한 스테이징 변경은 보존한다.
- 충돌, 훅 실패, 또는 커밋할 단위를 안전하게 나눌 수 없는 경우에는 실행을 멈추고 원인과 필요한 선택지를 설명한다.
- 사용자가 메시지, 포함 범위, 또는 커밋 개수를 지정하면 그 지시를 우선한다.
